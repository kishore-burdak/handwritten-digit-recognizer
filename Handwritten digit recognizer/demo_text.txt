INTRODUCTION

1.1 Background and Motivation
Machine learning has transitioned from a research curiosity to a central pillar of
modern technology. Organizations across industries — healthcare, finance,
logistics, and retail — deploy predictive models at massive scales. However, the
process of building a reliable model remains labor-intensive and error-prone. A
data scientist must select algorithms, engineer features, tune hyperparameters,
validate models, and quantify uncertainty — a process that requires months of
expertise.
Automated Machine Learning (AutoML) emerged to democratize this process.
Systems like Google AutoML, H2O AutoML, AutoSklearn, and TPOT promised to
automate model selection and training. However, most commercial AutoML
systems suffer from a critical scientific flaw: they use static train-validation-test
holdouts that, while convenient, produce optimistically biased performance
estimates. When a practitioner evaluates 500 model configurations on the same
validation set, the reported accuracy reflects the best random draw from a
distribution — not the true generalization capability of the chosen model.
SAGE (Sequential Analysis & Genealogic Evolution) was designed to address
these fundamental flaws. It is a terminal-based, research-grade AutoML system
that enforces mathematical rigor at every stage: from data ingestion and leakage
detection through hyperparameter optimization and final uncertainty
quantification.

1.2 Problem Statement
Contemporary AutoML systems exhibit three critical failure modes that
compromise the scientific validity of their results:
Data Leakage: Preprocessing transformations (scaling, imputation,
encoding) fitted on the full dataset before cross-validation, leaking test
statistics into the training process, and inflating validation scores.
Optimistic Bias: Using a single static validation split for hyperparameter
search means the reported metric is the maximum of many random
evaluations, not an unbiased generalization estimate.
Epistemic Overconfidence: Reporting point-estimate accuracy scores
without formal uncertainty bounds, creating a false sense of model
reliability in production deployment.

The primary objectives of the SAGE AutoML internship project are:
1. Design and implement a True Nested Cross-Validation framework that

2. LITERATURE REVIEW
2.1 Evolution of AutoML
The AutoML paradigm began with early work on combined algorithm selection and
hyperparameter optimization (CASH). Thornton et al. (2013) introduced AutoWEKA, the first system to frame AutoML as a structured CASH problem solvable by
Bayesian optimization. Feurer et al. (2015) extended this with Auto-sklearn,
incorporating meta-learning and ensemble construction on top of scikit-learn
pipelines.
Google's AutoML systems brought the concept to commercial scale, optimizing
neural architecture search (NAS) for image classification. H2O AutoML (LeDell &
Poirier, 2020) provided accessible tree-based ensemble automation. TPOT (Olson
et al., 2016) introduced genetic programming for pipeline optimization. Despite their
achievements, most of these systems still rely on simple train-test splits or singlelevel cross-validation, leaving them vulnerable to optimistic bias.

2.2 Need for OpenBox / Black-box Optimization
Hyperparameter optimization (HPO) is the process of finding the optimal
configuration for a machine learning algorithm. Early approaches used grid search
— exhaustively evaluating all configurations in a predefined space — and random
search (Bergstra & Bengio, 2012). While random search outperforms grid search in
high-dimensional spaces, it remains sample-inefficient.
Black-box optimization methods treat the objective function (cross-validated model
performance) as a black box — queried only at sampled points, with no knowledge
of gradients or internal structure. Bayesian Optimization (BO) revolutionized this
space by building a probabilistic surrogate model of the objective function and
using an acquisition function (Expected Improvement, UCB) to intelligently select
the next query point.
OpenBox (Li et al., 2021) introduced a generalized open-source framework for
black-box optimization that supports parallel evaluation, multi-fidelity optimization,
and transfer learning across tasks. In SAGE, we implement the same principles
through Optuna, using the Tree-structured Parzen Estimator (TPE) sampler — a
powerful Bayesian approach that models the distribution of good and bad
hyperparameter configurations separately. Why Black-box Optimization Matters
for AutoML

2.3 Conformal Prediction Theory
Conformal Prediction (Vovk et al., 2005) is a framework for constructing prediction
sets with guaranteed marginal coverage under the exchangeability assumption —
no parametric assumptions about the data distribution are required. For a userspecified confidence level 1-α (e.g., 95%), Conformal Prediction guarantees that
the true label falls within the prediction set for at least 1-α fraction of test samples.
The Split Conformal variant (Papadopoulos et al., 2002) is computationally efficient:
the model is trained once, a calibration set is held out, non-conformity scores are
computed, and the (1-α) quantile of these scores defines the prediction set
threshold. Unlike Bayesian credible intervals, conformal intervals are distributionfree and finitely valid.
Recent work by Angelopoulos & Bates (2021) in "A Gentle Introduction to
Conformal Prediction" has made the framework accessible for practical
deployment. SAGE implements split conformal prediction natively for both
classification (prediction sets) and regression (interval prediction).

5. OPENBOX AUTOML: WHO WE USED IT
5.1 What is OpenBox / Black-box Optimization
OpenBox is a generalized system for black-box optimization (BBO) — the problem
of finding the global optimum of an objective function f(x) when we have no
analytical form, no gradients, and evaluations are expensive. In the context of
AutoML, x represents a hyperparameter configuration and f(x) is the crossvalidated model performance.
The core challenge is sample efficiency: each evaluation of f(x) requires training
and evaluating a full ML model, which may take minutes or hours. A naive
approach (grid search over thousands of configurations) is computationally
infeasible. OpenBox's family of algorithms — based on Bayesian Optimization —
dramatically reduces the number of evaluations required to find near-optimal
configurations.

5.2 Optuna as the OpenBox Engine
SAGE uses Optuna (Akiba et al., 2019) as its black-box optimization engine.
Optuna is a framework-agnostic hyperparameter optimization library that
implements multiple search strategies and provides define-by-run style API for
dynamic search space specification.
15

Optuna was chosen over alternatives (Hyperopt, Ray Tune, Scikit-Optimize) for
the following reasons:
Define-by-run API: The search space is defined dynamically within the
objective function, allowing algorithm-conditional parameters (e.g.,
XGBoost's max_depth exists only for tree models, not linear models)
Efficient TPE Sampler: Optuna's default TPE implementation achieves
state-of-the-art sample efficiency across benchmark suites
Built-in pruning: MedianPruner and PercentilePruner can terminate
unpromising trials early, further reducing computation
Clean integration: Optuna's Study/Trial API integrates seamlessly with
scikit-learn Pipelines via cross_validate
Visualization utilities: Built-in plot functions for optimization history,
parameter importance, and contour plots

5.3 TPE Sampler — Tree-structured Parzen Estimator
The Tree-structured Parzen Estimator (TPE), introduced by Bergstra et al. (2011),
is the algorithmic heart of Optuna's search strategy. Unlike classical Bayesian
Optimization that models P(score | config), TPE models two separate distributions:
l(x): Distribution of configurations that achieved above-threshold
performance (top γ% of trials)
g(x): Distribution of configurations that achieved below-threshold
performance (bottom 1-γ% of trials)

∝

The acquisition function is the Expected Improvement (EI) ratio: EI(x)
l(x) / g(x).
TPE samples new configurations by maximizing this ratio — sampling from l(x)
while dividing by g(x) ensures the sampler focuses on regions where good
configurations are densely distributed and bad configurations are sparse.
In SAGE, each algorithm uses 5 Optuna trials (n_trials=5) with a TPE sampler
seeded at 42 for reproducibility. The hyperparameter spaces are carefully defined
to cover the practically relevant range without unnecessary breadth:

6. NESTED CROSS – VALIDATION DESIGN
6.1 The Leakage Problem in Standard AutoML
The most pervasive source of inflated AutoML performance is the misuse of the
validation set. Consider the following common workflow: split data 80/20, train
100 model configurations on the 80% split, evaluate all on the 20% validation
split, select the best. The reported validation score is biased because the
selection process used the validation set as a selection criterion.
Mathematically, if we evaluate N models and select the maximum,
E[max(X₁,...,Xₙ)] > E[Xᵢ] for any fixed i. This selection bias grows logarithmically
with N — evaluating 100 configurations on the same validation fold can
overestimate true performance by 3–8 absolute percentage points in empirical
studies (Cawley & Talbot, 2010).
A secondary source of leakage is preprocessing leakage: fitting a
StandardScaler, SimpleImputer, or SelectKBest on the full dataset (including
validation fold) before cross-validation allows test statistics (mean, std, feature
rankings) to contaminate the training process.

6.2 SAGE's Strict Nested Isolation Protocol
SAGE implements True Nested Cross-Validation (Phase A) with strict inner-outer
fold isolation:
Outer evaluation (3-fold StratifiedKFold for classification, KFold for
regression): Provides unbiased generalization estimate; outer fold test
data is NEVER seen during inner HPO
Inner optimization (3-fold CV within Optuna objective): Optuna's 5 trials
evaluate configurations only on inner folds; outer test data remains sealed
Preprocessing isolation: The dynamic pipeline (StandardScaler,
SimpleImputer, OHE, SelectKBest) is built INSIDE the objective function
and fitted INSIDE cross_validate — never on held-out data
The scikit-learn Pipeline object is the enforcement mechanism: when
cross_validate(pipeline, X, y, cv=inner_cv) is called, Pipeline.fit_transform() is
called only on the training portion of each fold, and Pipeline.transform() (not
fit_transform) is called on the validation portion. This guarantees zero leakage.

7. CONFORMAL PREDICTION & UNCERTAINTY
QUANTIFICATION
After Phase A (nested CV) identifies optimal hyperparameters for each model, Phase B
synthesizes the ten base learners into a calibrated stacking meta-ensemble. The final output
includes not just point predictions but formally guaranteed prediction sets/intervals via
Split Conformal Prediction.

7.1 Classification — Prediction Sets
For classification, non-conformity scores are defined as: s(xᵢ, yᵢ) = 1 − f̂(xᵢ)[yᵢ], where f̂(x)
[y] is the calibrated probability assigned to the true class. Intuitively: if the model is
confident and correct, this score is near 0; if the model assigns low probability to the true
class, the score is near 1.
Given a calibration set of size n, the (⌈(n+1)(1-α)⌉ / n)-quantile q̂̂ of the calibration scores
defines the threshold. At test time, the prediction set C(x) includes all classes y for which
f̂(x)[y] ≥ 1 − q̂̂ .
FORMAL COVERAGE GUARNTEE
P(Y_test C(X_test))≥1 − α

No parametric assumptions — valid for any data distribution

7.2 Regression — Prediction Intervals
For regression, non-conformity scores are absolute residuals: s(xᵢ, yᵢ) = |yᵢ − f̂̂(xᵢ)|.
The quantile q̂̂ defines symmetric intervals: Ĉ(x) = [f̂̂(x) − q̂̂ , f̂̂(x) + q̂̂ ], with formal
guarantee P(Y

The mean interval width (2q̂̂ ) quantifies epistemic uncertainty — wider intervals
indicate that the model's residuals on the calibration set are large, signaling either
high inherent noise or insufficient model capacity for the regression task.

11.MLFLOW EXPERIMENT TRACKING
Reproducibility is a first-class requirement in SAGE. Every model training run is
logged to a local MLflow tracking server (file:./mlruns) with full parameter and
metric provenance. MLflow provides the experiment management infrastructure
that transforms SAGE from a one-shot script into a reproducible research system.

11.1 What is MLflow
MLflow is an open-source platform for the machine learning lifecycle, developed
by Databricks. It provides four components: Tracking (logging parameters,
metrics, artifacts), Projects (packaging ML code for reproducibility), Models
(model registry and deployment), and Model Registry (centralized model
versioning).
SAGE uses MLflow Tracking with the following logging structure:
Experiment Name: SAGE_Omni_Suite — all runs grouped under this
experiment for easy comparison
Run Name: SAGE_PhaseA_{model_name} — one MLflow run per base
learner per execution
Parameters: Best hyperparameters discovered by Optuna (n_estimators,
learning_rate, max_depth, etc.)
Metrics: Primary score (ROC-AUC or R²) from inner nested CV evaluation
Tags: Task type, dataset shape, and pipeline configuration metadata

The report generation phase computes SHAP (SHapley Additive exPlanations)

12. CONCLUSION
12.1 Summary of Achievements
Thisinternship project successfully designed and implemented SAGE AutoML — a
research-grade Automated Machine Learning system that addresses fundamental
scientific shortcomings in conventional AutoML frameworks. The key achievements
are:
1. Implemented True Nested Cross-Validation with zero preprocessing
leakage through scikit-learn Pipeline isolation — eliminating selection bias
from hyperparameter optimization.
2. Built a diverse 10-algorithm ecosystem spanning gradient boosting
(LightGBM, XGBoost, CatBoost), ensemble methods (HistGBM, RF,
ExtraTrees, AdaBoost), linear models, KNN, and MLP — capturing
complementary inductive biases.
3. Deployed Optuna with TPE Sampler as the black-box optimization engine,
achieving near-optimal hyperparameter configurations in 5 trials per model
through Bayesian surrogate modeling.
4. Implemented native Split Conformal Prediction providing distribution-free,
finite-sample 95% marginal coverage guarantees for both classification
and regression.
5. Developed Mutual Information-based leakage detection with automatic
feature quarantine, preventing production models from relying on targetleaky features.
6. Integrated Isotonic Regression calibration (CalibratedClassifierCV) to
minimize ECE, producing well-calibrated probability estimates from the
stacking meta-ensemble.
7. Connected a local Mistral LLM for automated meta-insight synthesis,
translating raw metrics into actionable research-grade recommendations.
8. Delivered a polished terminal UI with Rich library visualizations, progress
tracking, and interactive pipeline transitions — making research-grade ML
accessible.

12.2 Limitations
Feature engineering is limited to SelectKBest — domain-specific feature
creation (polynomial features, interaction terms) is not automated.
The 5 Optuna trial limit prioritizes speed over exhaustiveness —
production deployments should use n_trials ≥ 50.
